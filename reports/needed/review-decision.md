# Scientific review decision record

Copy this form for one review question. Leave the decision as `not_received` until a qualified reviewer actually returns a dated, source-bound decision. Keep permission and scientific judgments separate.

| Field | Record |
| --- | --- |
| Review ID from `scientific-review.csv` |  |
| Claim report path(s) and SHA-256 |  |
| Supporting material path(s) and SHA-256 |  |
| Source-request ID(s), if any |  |
| Exact claim and population being decided |  |
| Exact question and exclusions from decision scope |  |
| Source custodian/permission authority and material version |  |
| Analytical and redistribution terms, with source evidence |  |
| Reviewer name, affiliation and relevant qualification |  |
| Independence and conflicts relative to source, model and target selection |  |
| Evidence actually inspected, including missing or inaccessible items |  |
| Decision: `not_received`, `accepted_scoped`, `accepted_with_conditions`, `refused`, or `deferred_for_source` | `not_received` |
| Rationale, uncertainty and unresolved conditions |  |
| Decision date and signed/verifiable evidence path |  |
| Named admission consumer and exact follow-up calculation or report change |  |
| New claim/material SHA-256 after any revision |  |

A result for one core, window, taxon axis or reference population does not transfer to another without its own source binding and decision. Record an unavailable input as unavailable, a refused result as refused, and an unevaluated outcome as unevaluated; none is a zero-accuracy score. Do not treat a source-use permission or a model replay as independent scientific endorsement.
